# 08. クラスと可変状態

ここまで型と関数を見てきました。再生中のプレイヤーは、それらを **時間とともに書き換える機械** です。`AudioPlayer` がそれです。

対応コード: `src/Player.fs`

この回に演習ファイルはありません。`Player.fs` を上から追うのが課題です。

## なぜクラスか

関数だけでも状態は持てます。レコードを毎回作り直して返す方法です。ただ、このアプリでは次が同時に動きます。

- NAudio の出力デバイス
- 開いている `WaveStream`
- スペクトル解析器
- バックグラウンドのリップ
- 再生終了イベント

これらは「今の Disc レコード」より寿命が長く、破棄が必要です。クラス + `IDisposable` が自然です。

```fsharp
type AudioPlayer() =
    let bands = EqPreset.createBands ()
    let mutable disc = DemoDisc.create ()
    let mutable state = Stopped
    ...
```

`type Name() =` が、引数なしコンストラクタのクラスです。

## let と let mutable と member

クラス本体のインデントに 3 種類あります。

```fsharp
let gate = obj ()                 // 外から見えない。不変の参照
let mutable volume = 0.85f        // 外から見えない。書き換え可
member _.Volume = volume          // 外から読めるプロパティ
member _.AdjustVolume(delta) =    // 外から呼べるメソッド
    volume <- Math.Clamp(volume + delta, 0.f, 1.f)
```

`member _.Foo` の `_` は「self を使わない」です。`this` が必要なときは `member this.LoadFolder` と書きます。同じクラスの他メソッドを呼ぶためです。

画面（`View`）は `member` だけを見ます。内部の `output` や `stream` は公開しません。

## 書き換え

```fsharp
state <- Playing
status <- $"{track.Title}  /  {eqNote}"
```

`<-` は可変セルへの代入です。`let` の「名前を付ける」とは別物です。

可変レコードフィールドはドットの右です。

```fsharp
band.GainDb <- EqPreset.clampGain (band.GainDb + delta)
```

## lock

音声スレッドと UI ループが同じ状態を触ります。再生が終わった通知は NAudio のスレッドから来ます。

```fsharp
let gate = obj ()

player.PlaybackStopped.Add(fun _ ->
    if not ignoreStop && state = Playing then
        lock gate (fun () -> onEnded ()))
```

`TogglePlay` や `Seek` も `lock gate` の中です。同じ鍵で、同時に `playAt` しないようにしています。

ロックの中で長い I/O をしない、が目安です。リップ本体は `Task.Run` に逃がし、進捗だけ `ripState <- ...` しています。

## 相互再帰: rec と and

`playAt` は曲の終わりで `onEnded` を呼び、`onEnded` はまた `playAt` を呼びます。F# は下の関数を上から見えないので、`let rec` と `and` でつなぎます。

```fsharp
let rec playAt (index: int) =
    ...
and onEnded () =
    match repeat with
    | RepeatOne -> playAt currentIndex
    | RepeatAll -> playAt (nextIndex true)
    | RepeatOff -> ...
and nextIndex (wrap: bool) =
    ...
```

`repeat` という DU が、次に何を呼ぶかを決めています。08 のクラスと 03 の DU がここで合流します。

## option で「今ないリソース」

```fsharp
let mutable output: IWavePlayer option = None
let mutable stream: WaveStream option = None
```

停止中はデバイスがありません。`null` ではなく `None` です。解放は `match` です。

```fsharp
match output with
| Some player ->
    try player.Stop() with _ -> ()
    try player.Dispose() with _ -> ()
| None -> ()

output <- None
```

`releaseWave` がこのパターンの塊です。新しい曲を鳴らす前に、前の機械を必ず止めます。

## IDisposable

```fsharp
interface IDisposable with
    member _.Dispose() =
        ripCancel <- true
        running <- false
        releaseWave ()
        Mci.close ()
        closeDigitalHandle ()
```

`App.run` は `use player = new AudioPlayer()` です。`use` はスコープを抜けたとき `Dispose` を呼びます。C# の `using` です。

コンソールを閉じても、CD ハンドルと WinForms のミラー窓が残りにくいようにしてあります。

## Pending でループを抜ける

キーボード処理の中でフォルダ選択ダイアログを出すと、ライブ描画と喧嘩します。だから `AudioPlayer` は「やってほしいこと」だけ覚えます。

```fsharp
member _.RequestOpenFolder() = pending <- OpenFolder
member _.ClearPending() =
    let p = pending
    pending <- Idle
    p
```

`App.live` が `Pending` を見てループを抜け、プロンプトを出し、また `live` します。クラスは UI を直接出さず、DU で合図します。
