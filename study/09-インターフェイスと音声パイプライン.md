# 09. インターフェイスと音声パイプライン

NAudio は「サンプルの列を読むもの」を `ISampleProvider` としてつなぎます。F# では、そのインターフェイスを型で実装します。

対応コード: `src/Equalizer.fs`, `src/Spectrum.fs`, `src/DemoSignal.fs`, `Player.playAt`

FFT の数式は理解しなくて大丈夫です。データの流れだけ追います。

## パイプラインの絵

デジタル経路は、だいたいこうです。

```
WaveStream（CD / ファイル / デモ）
    → ToSampleProvider()     float32 のサンプル
    → EqualizerProvider      10 バンドのピーク EQ
    → VolumeSampleProvider   音量
    → SpectrumTapProvider    解析用に覗く（音は変えない）
    → WaveOutEvent           デバイスへ
```

`playAt` の該当箇所です。

```fsharp
let samples = wave.ToSampleProvider()
let eq = EqualizerProvider(samples, bands)
let vol = VolumeSampleProvider(eq)
let tap = SpectrumTapProvider(vol, analyzer)
player.Init(tap)
player.Play()
```

どれも「上流を 1 つ受け取り、自分も `ISampleProvider` である」形です。関数を合成するように、オブジェクトを合成しています。

MCI 経路はこのパイプに入りません。Windows に「このトラックを鳴らして」と頼むだけなので、EQ は音に乗りません。画面の注記の理由です。

## インターフェイス実装

```fsharp
type EqualizerProvider(source: ISampleProvider, bands: EqBand array) =
    ...
    interface ISampleProvider with
        member _.WaveFormat = source.WaveFormat

        member _.Read(buffer, offset, count) =
            let read = source.Read(buffer, offset, count)
            if not bypass then
                // buffer の各サンプルをフィルタ
            read
```

ポイントです。

1. コンストラクタ引数で上流 `source` を受け取る
2. `Read` でまず上流を読む
3. 読めた個数だけ加工し、同じ個数を返す
4. `WaveFormat` は上流をそのまま見せる

`SpectrumTapProvider` は加工せず、`analyzer.Add` してから同じ `read` を返します。覗き窓です。

## inherit

デモ音源はストリームです。サンプルプロバイダではなく、シークできるバイト列として振る舞います。

```fsharp
type DemoWaveStream(kind: DemoKind, duration: TimeSpan) =
    inherit WaveStream()
    ...
    override _.Read(buffer, offset, count) =
        // フレーム番号から正弦波などを計算して PCM を書く
```

`override` が基底の抽象メンバーです。`interface ... with` と形は似ていますが、継承か実装かの違いです。

学習時点では、「NAudio が欲しがる穴を、F# の型で埋める」と覚えれば十分です。

## バッファは可変

関数型の授業では配列を書き換えないと教えます。音声では、同じ `float32[]` をその場で更新します。毎秒何万サンプルも新しい配列にしている余裕がないからです。

```fsharp
let mutable sample = buffer[offset + n]
sample <- filter.Transform(sample)
buffer[offset + n] <- Math.Clamp(sample, -1.f, 1.f)
```

ドメインの `Disc` は不変、音声ホットパスは破壊的、がこのコードベースの境界です。

## スペクトルは「覗いた結果のスナップショット」

`SpectrumAnalyzer` は FFT サイズ分ためてから棒グラフを更新します。画面は 50ms ごとに `Snapshot()` します。

```fsharp
member _.Snapshot() =
    lock gate (fun () -> Array.copy bars, Array.copy peaks)
```

コピーを返すので、描画中に解析スレッドが配列を壊しません。`View.spectrum` はその配列をブロック文字にします。

停止中は `Tick` から `Decay` を呼び、棒がゆっくり落ちます。

## デモ信号が教材になる理由

`DemoWaveStream` はファイルも CD も使いません。`kind` で波形を切り替えます。

| `DemoKind` | 中身 | EQ の試し方 |
|------------|------|-------------|
| `Noise` | 疑似ホワイトノイズ | どのバンドを動かしても反応する |
| `Bass` | 55 / 82.5 / 110 Hz | 低域バンド |
| `Chord` | 和音と倍音 | 中域 |
| `Sweep` | 40Hz→16kHz | 全バンドを順に通過 |

`--demo` で講座を進められるのは、この型があるからです。ハードウェアのレッスンを後回しにできます。

## Win32 は「後回しでよい」

`CdDrive.fs` と `ShareWindow.fs` は `DllImport` です。F# の学習というより、プラットフォーム API です。

読むときの最低限です。

- `extern` で C の関数を宣言する
- `nativeint` がハンドル（ポインタ幅の整数）
- `Result` で失敗を返す（06 の延長）

CD の TOC や `PrintWindow` は、F# が分かってからで構いません。
