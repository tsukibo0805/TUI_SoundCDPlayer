# 07. コレクションとパイプライン

SOUND は「曲の列」「引数の列」「バンドの列」をよく変換します。F# ではループより、`map` / `filter` / `choose` をパイプで繋ぎます。

対応コード: `Player.LoadFolder`、`Program.ripCli`、`DemoDisc.create`

演習: `study/exercises/06-collections.fsx`

## 3 つの器

| 型 | リテラル | 特徴 | このアプリ |
|----|----------|------|------------|
| 配列 | `[| 1; 2 |]` | インデックスが速い。可変長にしない | `Disc.Tracks`, `EqBand[]` |
| リスト | `[ 1; 2 ]` | 先頭への追加が速い。不変 | 小さな一時データ |
| シーケンス | `seq { ... }` | 遅延。`IEnumerable` | フォルダ走査の途中 |

`LoadFolder` は seq で絞ってから、最後に配列へ確定します。

```fsharp
Directory.EnumerateFiles(path, "*.*", SearchOption.AllDirectories)
|> Seq.filter (fun f -> audioExtensions.Contains(Path.GetExtension(f).ToLowerInvariant()))
|> Seq.sort
|> Seq.toArray
```

`EnumerateFiles` は見つかった順に少しずつ出ます。全部配列にしてから `filter` するより軽いことがあります。

## map / mapi

`map` は「各要素を変換して、同じ長さの新しい列」です。

```fsharp
files
|> Array.mapi (fun i file -> {
    Index = i
    Number = i + 1
    Title = Path.GetFileNameWithoutExtension(file)
    Duration = dur
    Source = AudioFile file
    Rip = None
})
```

`mapi` はインデックス付きです。トラック番号は 1 始まりなので `i + 1` です。

`DemoDisc.create` も同じ型を `Array.mapi` で作っています。音源がファイルかデモかの違いだけです。

## filter と choose

`filter` は残す／捨てるです。中身の型は変わりません。

`choose` は「残すなら `Some x`、捨てるなら `None`」です。残した値の型を変えられます。

```fsharp
disc.Tracks
|> Array.choose (fun t ->
    match t.Rip with
    | Some rip when trackFilter.IsNone || trackFilter = Some t.Number -> Some(t, rip)
    | _ -> None)
```

抽出対象だけを `(Track * RipInfo)` の配列にしています。`filter` してから `map` するより、1 回で「あるものだけ取り出す」が書けます。

## tryFind / tryPick / exists

| 関数 | 意味 | 戻り値 |
|------|------|--------|
| `Array.tryFind` | 条件を満たす最初の要素 | `'T option` |
| `Array.tryPick` | 条件を満たす最初の変換結果 | `'U option` |
| `Array.exists` | 1 つでも条件を満たすか | `bool` |
| `Array.forall` | 全部が条件を満たすか | `bool` |

`StartRip` は、全部 `Rip` が無いときだけ TOC を付け直します。

```fsharp
if disc.Tracks |> Array.forall (fun t -> t.Rip.IsNone) then
    attachRip ()
```

`--self-check` のスペクトル確認は `exists` です。

```fsharp
if bars |> Array.exists (fun x -> x > 0.f) then
    printfn "OK   spectrum energy"
```

## 集約

全部を 1 つの値に畳むときは `fold` か、専用関数です。

```fsharp
Array.sum
Array.length
Array.max
Array.truncate 8
String.concat "\n"
```

`View.plain` のトラック一覧は、最大 8 行に切ってから文字列へ畳んでいます。

```fsharp
disc.Tracks
|> Array.truncate 8
|> Array.map (fun t -> sprintf "%s %02d  %s  %s" ...)
|> String.concat "\n"
```

## for も使ってよい

パイプラインが読みにくいときは、普通のループで構いません。`EqualizerProvider` のサンプル処理や `SpectrumAnalyzer.Add` は、性能と添字計算のために `for` / `while` です。

目安です。

- 列を別の列に変える → `map` / `choose`
- 副作用（描画、I/O、配列の裏書き） → `for`
- 初期値から畳む → `fold`（このアプリでは少なめ）

## Set と Map

`LoadFolder` の拡張子集合です。

```fsharp
let audioExtensions =
    set [ ".wav"; ".mp3"; ".aiff"; ".aif"; ".wma"; ".m4a"; ".aac" ]
```

`set [ ... ]` は `Set<string>` です。`Contains` が速いです。

`StartRip` では TOC を番号で引くために `Map` を作ります。

```fsharp
toc
|> Array.choose (fun t -> t.Rip |> Option.map (fun r -> t.Number, r))
|> Map.ofArray
```

`Map.tryFind t.Number byNumber` は option を返します。無いキーで例外にしないのがポイントです。

## パイプラインを声に出す

次を日本語で読む練習をしてください。

```fsharp
let targets =
    pool
    |> Array.choose (fun t -> t.Rip |> Option.map (fun r -> t, r))
```

「`pool` の各トラックについて、`Rip` があるものだけ `(トラック, RipInfo)` にする」。これが読めたら、`ripCli` と `StartRip` の中核は理解できています。

## 本番コードを読む

1. `LoadFolder` の 4 段パイプを、段ごとにコメントする
2. `ripCli` の `targets` と `StartRip` の `targets` が、ほぼ同じ形なのを確認する

## 演習

`study/exercises/06-collections.fsx` で、パイプの各段を小さな関数として作ってから接続します。

1. 拡張子を得る → 小文字にする → 音声拡張子か判定する
2. 1ファイルを1レコードにする → `mapi` で配列全体へ広げる
3. `Rip` と曲番号の条件を1件について判定 → `choose` で配列全体へ広げる
4. 件数を切る → 表示文字列へ変換する → 改行で連結する

途中関数のテストもあるため、長いパイプライン全体を一度にデバッグする必要はありません。
