# 05. パターンマッチ

`match` は F# の場合分けです。if の強化版ではなく、型を分解する道具です。

対応コード: `src/App.fs` の `Input.handle`、`src/Player.fs` の `playAt`

演習: `study/exercises/04-matching.fsx`

## 基本形

```fsharp
match state with
| Playing -> "再生"
| Paused -> "一時停止"
| Stopped -> "停止"
```

上がった順に試し、最初に一致した枝を実行します。戻り値の型は全枝で揃えます。

`if` でも書けますが、場合が増えるほど `match` の方が安全です。ケースを足すとコンパイラが未処理を指摘します。

## データを取り出す

```fsharp
match track.Source with
| AudioFile path -> path
| DemoTone kind -> string kind
| DigitalCd(_, lba, sectors) -> $"LBA {lba} / {sectors}"
| MciCd(drive, number) -> $"{drive}: track {number}"
```

`DigitalCd(_, lba, sectors)` の `_` はハンドルを捨てています。名前を付ける順番は、型定義のフィールド順です。

## when ガード

追加条件は `when` です。

```fsharp
match player.Pending with
| Quit -> exit <- true
| OpenFolder -> exit <- true
| RipPrompt -> exit <- true
| Idle ->
    player.Tick()
```

`Input.handle` では、キーとフォーカスを同時に見ます。

```fsharp
match key.Key, key.KeyChar, player.Focus with
| ConsoleKey.LeftArrow, _, Equalizer -> player.MoveEq -1
| ConsoleKey.LeftArrow, _, TrackList -> player.Seek(TimeSpan.FromSeconds -5.0)
| _, ('+' | '='), _ -> player.AdjustEq 1.f
| _, '?', _ -> player.ToggleHelp()
| _ -> ()
```

読み方です。

1. タプル `(キー, 文字, フォーカス)` を一度にマッチ
2. `Equalizer` の左矢印はバンド移動、`TrackList` ならシーク
3. `'+' | '='` は「どちらか」
4. 最後の `_` が「どれでもない。何もしない」

同じキーでも、フォーカスというデータで意味が変わります。フラグを先に if するより、場合を表に並べた方が追いやすいです。

## 定数・範囲・OR

```fsharp
match n with
| 0 -> "なし"
| 1 | 2 | 3 -> "少ない"
| x when x < 0 -> "不正"
| x -> string x
```

文字の OR は `Input` でも使っています。`,` と `[` が音量ダウンです。

## 入れ子と option

```fsharp
match track.Rip with
| Some rip -> rip.StartLba
| None -> -1
```

`Player.CurrentTrack` は `Track option` です。`View.fs` ではこう使います。

```fsharp
let title =
    track
    |> Option.map (fun t -> t.Title)
    |> Option.defaultValue "—"
```

`match` でも書けます。パイプラインの方が「無かったらダッシュ」が短くなります。どちらも同じ意味です。

## 配列パターン

`Mci.parseMmssff` は、分割した文字列の個数で分岐します。

```fsharp
match parts with
| [| m; s; f |] -> ...
| [| t; m; s; f |] -> ...
| _ -> None
```

`[| ... |]` は「この長さの配列で、各要素をこの名前に束縛」です。MCI が `mm:ss:ff` を返すか `track:mm:ss:ff` を返すかの差を、型に近い形で受けています。

list なら `[ m; s; f ]`、先頭だけ取るなら `head :: tail` です。このアプリでは配列の方が多いです。

## 網羅性

次はコンパイルできません（警告またはエラー）。

```fsharp
match state with
| Playing -> "on"
| Paused -> "pause"
```

`Stopped` が無いからです。`_` で黙らせることはできますが、新しいケースを足したときに気づけなくなります。ドメインの DU では、できるだけ全部書きます。

外側の `Input.handle` のように、本当に「その他は無視」なら `_ -> ()` が正しいです。

## 相互再帰の match

`playAt` は音源の種類で再生経路を分けます。

```fsharp
match track.Source with
| MciCd(drive, number) ->
    // winmm の MCI。EQ は乗らない
| source ->
    // WaveStream を作り、EQ → 音量 → スペクトルへ渡す
```

同じ `Track` でも、中の DU で処理が大きく分岐します。状態を `string mode` にせず、`TrackSource` に寄せてあるおかげです。

1. 抽出中は `S` / `Esc` / `Q` だけ受け付ける
