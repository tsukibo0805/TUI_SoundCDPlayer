## ファイル地図

```

  ├─ CLI    --help / --rip / --self-check / --smoke
  └─ TUI    App.run
               ├─ 引数消費（demo / cd / フォルダ）
               ├─ 初期 CD 検出

                    ├─ Input.handle  → AudioPlayer のメソッド

AudioPlayer

  ├─ playAt                         CdWaveStream / AudioFileReader / DemoWaveStream / Mci
```

迷ったら、今見ている値がどの型か `Domain.fs` に戻ります。

## ゼロから作るならこの順

レッスンと同じです。1 段ごとに `dotnet build` が通る状態を目指します。

### 1. 型だけ（レッスン 03–04）

`PlaybackState`, `RepeatMode`, `Track`, `Disc` を書く。まだ音は出さない。

### 2. 純関数（レッスン 02）

`TimeFmt.mmss` と、必要なら `CdMath`。`--self-check` の原型になる。

### 3. デモ盤（レッスン 03, 07）

`DemoDisc.create`。配列とレコードの組み立て。

### 4. プレイヤー状態（レッスン 08）

`AudioPlayer` 相当を、最初は「今のインデックスと State だけ」で作る。`TogglePlay` が `Stopped`/`Playing`/`Paused` を回ればよい。音は後。

### 5. キーとループ（レッスン 05, 10）

コンソールでキーを読み、状態を印字する。Spectre は後からでよい。

### 6. デモ再生（レッスン 09）

`DemoWaveStream` と `WaveOutEvent`。EQ なしで 1 曲鳴れば勝ち。

### 7. フォルダ盤（レッスン 06–07）

`LoadFolder` のパイプ。

### 8. EQ とスペクトル（レッスン 09）

`ISampleProvider` を 1 段足す。

### 9. TUI（レッスン 10）

`View` をパネルに分ける。

### 10. CD とリップ

Win32。F# の問題より OS の問題。管理者権限やドライブ差が出る。

講座を全部読んだ今、1〜7 は自分の言葉で書けるはずです。8 以降は本番を写しながらで十分です。

## 機能を足すときの手順

例: 「B キーで先頭の曲に戻る」。

1. 新しい状態が要るか？ 不要なら `Domain.fs` は触らない
2. `AudioPlayer` にメソッドを足す（`playAt 0`）
3. `Input.handle` に 1 枝を足す
4. `View` のフッターとヘルプに 1 行足す
5. `dotnet run -- --demo` で B を押す

型が足りない機能（新しいリピートモードなど）は、先に DU のケースを足します。`match` が赤くなった場所が、直す一覧です。

## よく詰まる点

**コンパイル順**  
新しいファイルを fsproj に足す位置を間違えると、「型が無い」と出ます。使う側より上に置きます。

**float と float32**  
`1.0` と `1.f` は別型です。EQ は `float32` です。

**option を `.Value` で開けない**  
`.Value` は `null` 参照に近いです。`match` か `Option.defaultValue` を使います。

**mutable を増やしすぎる**  
新しいフラグを足したくなったら、既存の DU にケースを足れないか先に考えます。`RipState` と `PendingAction` がその見本です。

**例外を飲み込みすぎる**  
`with _ -> ()` は境界（破棄、壊れたファイル）用です。自分の計算では Result を返します。
