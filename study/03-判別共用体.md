# 03. 判別共用体

判別共用体（discriminated union, DU）は、このアプリで一番大事な型です。「この値は、次のうちどれか 1 つ」を型で固定します。

対応コード: `src/Domain.fs` の `PlaybackState`, `RepeatMode`, `FocusPane`, `TrackSource`, `RipState`

演習: `study/exercises/02-unions.fsx`

## 場合が列挙できるとき

再生状態は 3 つしかありません。

```fsharp
type PlaybackState =
    | Stopped
    | Playing
    | Paused
```

これは C# の `enum` に似ています。違うのは、各ケースに **データを載せられる** ことです。

```fsharp
type TrackSource =
    | DigitalCd of handle: nativeint * startLba: int * sectors: int
    | MciCd of drive: string * trackNumber: int
    | AudioFile of path: string
    | DemoTone of kind: DemoKind
```

「トラックの音源」は 4 通りで、それぞれ必要な情報が違います。

- デジタル CD … ハンドルと開始 LBA とセクタ数
- MCI CD … ドライブレターとトラック番号
- ファイル … パス
- デモ … 信号の種類

クラス継承や `null` 可能なフィールドの塊で表すより、先に場合を並べた方が漏れに気づけます。

## 作る・分解する

作るときはケース名を書きます。

```fsharp
let src = AudioFile @"C:\music\01.wav"
let demo = DemoTone Chord
```

分解は `match` です。

```fsharp
let label source =
    match source with
    | DigitalCd _ -> "CD DIGITAL"
    | MciCd _ -> "CD MCI"
    | AudioFile path -> path
    | DemoTone kind -> string kind
```

`_` は「中身は今使わない」です。`AudioFile path` のように名前を付けると、そのデータを取り出せます。

コンパイラは、どれかを書き忘れると警告します。新しい音源を足したとき、呼び出し側の `match` が赤くなるので、修正箇所が分かります。

## ケースにデータを載せる書き方

よく見る形は 3 つです。

```fsharp
| Stopped                          // データなし
| AudioFile of path: string        // 名前付き 1 つ
| RipDone of files: int * destination: string   // タプル
```

`RipState` は状態機械そのものです。

```fsharp
type RipState =
    | RipIdle
    | RipRunning of RipProgress
    | RipDone of files: int * destination: string
    | RipFailed of message: string
    | RipCanceled of destination: string
```

「抽出していない / 進行中 / 成功 / 失敗 / キャンセル」が同時に成り立つことはありません。進行中のときだけ `RipProgress` を持ちます。

`Player.IsRipping` は、この型のおかげで 1 つの `match` で済みます。

```fsharp
member _.IsRipping =
    match ripState with
    | RipRunning _ -> true
    | _ -> false
```

## メンバーを付けられる

DU にもメソッドを付けられます。`RepeatMode` が典型です。

```fsharp
type RepeatMode =
    | RepeatOff
    | RepeatAll
    | RepeatOne

    member this.Label =
        match this with
        | RepeatOff -> "OFF"
        | RepeatAll -> "ALL"
        | RepeatOne -> "ONE"

    member this.Next() =
        match this with
        | RepeatOff -> RepeatAll
        | RepeatAll -> RepeatOne
        | RepeatOne -> RepeatOff
```

`R` キーは `repeat <- repeat.Next()` だけです。if の連鎖より、循環が型の隣に置いてあります。

`FocusPane` も同じです。`Tab` で `TrackList` と `Equalizer` を入れ替えます。

## このアプリの DU 一覧

`Domain.fs` を上から見て、次を対応づけてください。

| 型 | 意味 | 場合の数 |
|----|------|----------|
| `RepeatMode` | リピート | 3 |
| `PlaybackState` | 再生状態 | 3 |
| `FocusPane` | 今フォーカスしている枠 | 2 |
| `DemoKind` | デモ信号の種類 | 4 |
| `TrackSource` | そのトラックをどこから鳴らすか | 4 |
| `RipState` | CD 抽出の進捗 | 5 |
| `DiscKind` | ディスクの種類 | 4 |
| `PendingAction` | メインループを一度抜ける理由 | 4 |

`PendingAction` は少し特殊です。フォルダ選択やリップ確認は Spectre のプロンプトなので、ライブ描画ループを抜けてから行います。

```fsharp
type PendingAction =
    | Idle
    | OpenFolder
    | RipPrompt
    | Quit
```

「ループの外でやりたい仕事」も、フラグの束ではなく 1 つの DU です。

## enum との使い分け

データが乗らないなら、見た目は enum と同じです。それでも F# では DU を使うことが多いです。あとからデータを足せるし、`match` の検査が同じだからです。

整数が欲しい本当の Win32 定数（IOCTL など）は、`CdDrive.fs` で普通の `let` になっています。型で場合分けする対象ではありません。
